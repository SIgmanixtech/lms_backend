# Backend (Next.js) rules

- This folder is the only server: every privileged operation is a route handler under `src/app/api/`; the frontend calls it through `src/lib/api/client.ts`, so no server code ships in the browser bundle.
- Every user endpoint is built with `endpoint()` in `src/lib/http/endpoint.ts` (origin allowlist, rate limits, Supabase token verification, role check, bounded JSON body, zod validation, safe `AppError` responses), so no route can skip a check.
- Each role has its own versioned REST API: `/api/v1/admin/*`, `/api/v1/tutor/*` (role value `trainer`), `/api/v1/student/*`, listed once in `ROLE_API` (contracts.ts: method, path with `:params`, roles). Each operation has one handler in `src/api/role-handlers.ts`; the route file in each allowed role folder only calls `roleRoutes("<role>", [ops])`, so behaviour is identical across roles and the server admits only that role on that path. `:params` live in `[id]`/`[subId]` folders and are merged over the body/query before validation. No shared role groups; `tests/route-access.test.ts` enforces this. Session routes are `/api/v1/auth/*` (`access: "signed-in"`); `/api/public` and `/api/health` stay unversioned (external schedulers and the host health check use them).
- Authorization first runs as the caller (`auth.supabase`, RLS-scoped) or via an authorizing RPC; `supabaseAdmin` is used only after that, because the service-role client bypasses RLS.
- Paths and response types live in `src/lib/api/contracts.ts` (shared with the frontend); `tests/route-access.test.ts` fails if a contract path has no route or a route is missing from the contract.
- Pure rules (schemas, policies, `AppError`, DB types) are copied from the frontend into `src/shared` (`npm run sync-shared`, never edited here) and imported via `@/`; backend-only code uses `@backend/`, so validation and decisions are identical on both sides.
- Auth uses bearer tokens only and CORS never allows credentials, so cookies are never involved and CSRF doesn't apply.
- `/api/public/*` routes take no user token: bootstrap and cron require their shared secrets (constant-time compare), and the recording stream requires a signed short-lived ticket, and file downloads (`/api/public/files`) require a Storage-signed short-lived token.
- The browser talks only to this backend: data via each role's own table/function/file endpoints (`/api/v1/<role>/...`, generated from contracts.ts by `npm run generate-routes`), sessions via `/api/v1/auth/login|refresh|logout`, files via `/api/public/files`; the frontend holds no Supabase URL or key.
